### Правила Vladimir Core (исходные, FORTS)
| Элемент | Правило |
|---|---|
| Уровни (D) | Подтвержденные пивоты дневного графика: 2 бара слева, 2 справа |
| Подтверждение (H1) | Нет «летящих ножей»/«палок» (импульс без базы). Нужна база (сжатие волатильности) или реакция (закрытие H1 за уровнем в сторону сделки) |
| Триггер пробоя (M5) | Минимум 2 закрытия M5 за уровнем |
| Триггер реакции (M5) | Касание → отскок → повторное касание с закрытием в сторону сделки |
| Вход | Всегда лимитный ордер, допуск 2–3 тика от уровня |
| Стоп / цели | Стоп 0.15 ATR(D); T1 0.5, T2 0.75, T3 1.0 ATR(D) |
| Прочее | «Середина диапазона» отключена |
| Базовая линия FORTS | 50–52 % винрейт, +35–45R/год на инструмент после издержек |

### Адаптация к крипте (что тестируем)
| Параметр | Диапазон |
|---|---|
| Стоп | 0.3–0.6 ATR(D) (`stop_atr_multiplier`) |
| Цели | Цели FORTS × 2 и × 3 (`VladimirParams.scaled_from_forts`) |
| H0 для сравнения | Параметры FORTS как есть (`VladimirParams.forts_baseline`) |

### Издержки (консервативно, для стресс-теста)
| Статья | Значение |
|---|---|
| Maker | 0.02 % (стремимся только к maker-входам) |
| Taker | 0.05 % (стопы, выход по времени) |
| Проскальзывание | Стресс: 0.1 % на вход и 0.1 % на выход, даже для лимиток (`CostModel.stress`) |
| Funding | Обязательно, по историческим ставкам |

### Риск-менеджмент
| Правило | Значение |
|---|---|
| Риск на сделку | 1 % депозита (fixed fractional) |
| Дневной лимит убытка | −2 % |
| Недельный лимит | −5 % |
| Жесткая остановка | Просадка −15 % от максимума |

## 2026-09-25 — решения по реализации v0 (принял Claude, пересматриваются по коду Vladimir Core)

1. **Формализация H1 «нож/палка»**: H1-бар длиннее `h1_knife_max_atr` = 0.5 ATR(D) среди последних 3 H1 → сигнал отклоняется. **База**: 4 H1-бара в диапазоне ≤ 0.35 ATR(D) у уровня (≤ 0.15 ATR). Это моя интерпретация словесного правила. Числа будут сверены с `scenario_engine.py`.
2. **Допуск входа** в крипте задан в долях ATR (0.01 ATR), а не в тиках: тик BTC (0.1 $) несопоставим с тиком Si.
3. **Лимитка у уровня не бывает «по рынку»**: для лонга цена ордера = min(уровень + допуск, текущая цена). Это сохраняет maker-исполнение.
4. **Выход по времени** 24 ч (на FORTS сделки закрывались в конце сессии; у крипты сессии нет). Параметр `max_hold_bars`.
5. **Бэктест консервативен**: лимитка исполняется только при проходе цены сквозь нее; при одновременном касании стопа и цели на одном баре считается стоп; стоп при гэпе — по open.
6. **«Середина диапазона»** в v0 не реализована. Нужен точный алгоритм из кода.
