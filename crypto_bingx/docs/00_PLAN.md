## 0. Главный вывод до начала работы (почему нельзя просто перенести систему)

Перед тестами я посчитал одно число, и от него зависит вся адаптация: **сколько стоит сделка в единицах риска R**.

| | FORTS (Si, пример) | BingX perp, BTC | BingX perp, ETH |
|---|---|---|---|
| Дневной ATR (типично) | ~1 000–1 500 пт | ~2.5–3.5 % | ~3.5–4.5 % |
| Стоп 0.15 ATR(D) | ~150–225 пт (₽) | **~0.4–0.5 %** | ~0.5–0.7 % |
| Комиссия + проскальзывание на круг | ~2–3 ₽ (≈ 1–2 % от R) | 0.10 % taker×2 + ~0.04 % проскальз. ≈ **0.14 %** | ≈ 0.14–0.20 % |
| **Издержки в R** | **≈ 0.01–0.02 R** | **≈ 0.3 R** | ≈ 0.25–0.35 R |

*(ATR здесь приблизительный, по памяти. Точные значения посчитаю на данных на этапе 1.)*

**Что из этого следует.** При винрейте 50 % и среднем выигрыше ~2R матожидание до издержек около +0.5R на сделку. На FORTS издержки почти ничего не отнимают. На крипте с тем же стопом 0.15 ATR комиссия и проскальзывание съедают **~60 % преимущества**. Поэтому при переносе на крипту обязательно нужно:
1. **Шире стоп** (0.3–0.6 ATR), меньше сделок, больше R на сделку;
2. **Входить лимитными ордерами** (maker) от уровня, а не по рынку. Методология Vladimir Core и так строится на уровнях, так что это получается естественно;
3. Учитывать **funding** (каждые 8 ч) для позиций, которые держатся дольше нескольких часов.

Это гипотеза, а не приговор. На этапе 1 проверю её на реальных данных в первую очередь.

## 2. Выбор активов (предварительный)

**Рынок:** USDT-M бессрочные фьючерсы BingX, в обе стороны.
- Комиссия ниже спота (стандарт BingX: maker 0.02 % / taker 0.05 % против 0.1 % на споте, точный тариф нужно проверить на твоем аккаунте);
- Есть шорты: система на уровнях без шортов теряет половину сигналов;
- **Плечо используется только ради эффективности маржи, а не для увеличения риска.** Риск задается размером позиции от стопа, как в Vladimir Core.

**Кандидаты для глубокого теста:** BTC, ETH, SOL, XRP, BNB, DOGE (при необходимости добавлю LINK/AVAX).
**Критерии отбора в финальные 3–5 монет:**
- история ≥ 4 лет M1/M5 (2021–2026: бычий рынок 2021, крах 2022 с LUNA и FTX, восстановление 2023–24, 2025–26);
- глубокий стакан на BingX (проскальзывание < 0.03 % на размере позиции);
- стабильный результат стратегии (а не лучший результат на истории, чтобы избежать подгонки);
- низкая взаимная корреляция сигналов.

Ожидаю, что в финале останутся **BTC + ETH + 1–3 ликвидных альта**. Мемкоины и низколиквидные альты не берем: они ненадежны для систематической торговли (делистинги, манипуляции, проскальзывание).

## 4. Гипотезы стратегий (тестирую все, выбираю по данным)

| # | Стратегия | Суть | Зачем |
|---|---|---|---|
| **H0** | Vladimir Core «как есть» | Точный порт D→H1→M5 с параметрами FORTS (стоп 0.15 ATR), день по UTC | Отправная точка: отвечает на вопрос «работает ли оригинал на крипте» |
| **H1** | Vladimir Core, адаптированный | Те же уровни, но: стоп 0.3–0.6 ATR, лимитный вход, D+W уровни, фильтр сессий, учет funding | Главный кандидат |
| **H2** | Vladimir Core на старших ТФ | D → H4 → H1 (или W → D → H4): меньше сделок, меньше доля издержек | Если на M5 издержки убивают результат |
| **H3** | Трендовый бенчмарк | Donchian/EMA-пробой на H4/D + таргетирование волатильности | Контрольная стратегия, широко описанная для крипты. Если H1 хуже нее, это важный сигнал |
| H4 | Фильтры поверх H1 | Режим (ADX/волатильность), funding-экстремумы, OI | Только если дают устойчивый прирост на walk-forward |

**ML:** на старте не использую. Имеет смысл только как фильтр сигналов (мета-разметка) после того, как базовая стратегия покажет преимущество. Иначе велик риск переобучения, а понятность системы падает.

## 5. Методика бэктеста (защита от самообмана)

1. **Издержки:** taker 0.05 %, maker 0.02 % (или по твоему тарифу), проскальзывание 0.02–0.05 % для BTC/ETH, до 0.1 % для альтов. **Отдельный стресс-тест при 0.1–0.3 %**, как ты просил. Funding фактический, по истории.
2. **Исполнение:** без заглядывания в будущее; лимитный ордер считается исполненным только при проходе цены *сквозь* уровень; если стоп и тейк оказались внутри одной свечи, считаю, что первым сработал стоп.
3. **Walk-forward:** окно обучения 12 мес. → тест 3 мес., со сдвигом. Параметры выбираю по **плато устойчивости**, а не по максимуму.
4. **Holdout:** последние ~6 мес. (апрель–сентябрь 2026) **не трогаю до самого конца**. Это финальный экзамен.
5. **Поправка на множественные тесты:** считаю, сколько вариантов перепробовано, и привожу Deflated Sharpe Ratio.
6. **Разбивка по режимам:** 2021 (бычий), 2022 (медвежий), 2023–24 (восстановление), 2025–26; тренд, флэт, высокая волатильность.
7. **Метрики:** винрейт, PF, средний R, матожидание в R, Sharpe/Sortino, max DD, Calmar, худший день, серии убытков, доля издержек в валовой прибыли. Сравнение с buy & hold BTC/ETH.

## 6. Критерии остановки (честность)

- Если **ни один вариант** не дает PF > 1.3 **после издержек на OOS walk-forward**, я прямо это сообщаю и не перехожу к разработке торгового движка.
- Если результат держится на одной монете или одном годе, стратегия отклоняется.
- Если на holdout результат падает более чем вдвое относительно walk-forward, возвращаюсь к исследованию, а не подгоняю параметры.

**Предупреждение насчет «обогнать buy & hold».** В бычьи годы (2021, 2023–24) BTC вырос в 2–3 раза. Стратегия с max DD < 25 % почти наверняка не обгонит его по абсолютной доходности в таких периодах. Предлагаю сравнивать по **доходности с поправкой на риск** (Sharpe, Calmar) и по **полному циклу** (включая 2022, когда BTC упал на −65 %). Подтверди, устраивает ли такая трактовка.

## 7. Архитектура будущей системы (черновик)

```
crypto-bingx/
├── data/        загрузка и хранение свечей (Parquet), проверка качества
├── strategy/    уровни, сигналы D/H1/M5 (одна логика и для бэктеста, и для live)
├── backtest/    событийный бэктестер, издержки, walk-forward, отчеты
├── risk/        размер позиции от R, лимиты: дневной, недельный, портфельный, max DD
├── execution/   BingX REST + WebSocket (ccxt + собственная обертка), сверка позиций
├── monitor/     Telegram-уведомления, алерты, дашборд, health-check
├── pine/        индикатор TradingView (визуализация тех же уровней и сигналов)
└── docs/        отчеты, инструкции, runbook при сбоях
```

- **Бумажная торговля:** через **демо-счет BingX (VST)**: настоящий API и настоящие ордера, но виртуальные деньги. Этот тест честнее, чем симуляция внутри скрипта.
- **Хостинг:** VPS (1–2 vCPU, 2 ГБ RAM) в регионе, откуда BingX API доступен стабильно; Docker + systemd с автоперезапуском.
- **Журнал:** SQLite (сделки, ордера, события) + лог-файлы с ротацией.
- **Безопасность ключей:** права только на торговлю, **вывод средств запрещен**, доступ только с IP сервера. Ключи хранятся в `.env` на сервере и никогда не попадают в git или чат.
